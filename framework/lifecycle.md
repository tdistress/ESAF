# Enterprise AI Lifecycle

**Status:** Working Draft

Every in-scope AI capability shall progress through a governed lifecycle appropriate to its risk and criticality.

| Stage | Primary outcome | Minimum evidence |
|---|---|---|
| Strategy | AI priorities aligned with enterprise objectives | AI strategy or roadmap |
| Ideation | Defined opportunity and accountable sponsor | Use-case proposal |
| Business case | Approved value hypothesis and success measures | Business case |
| Risk classification | Risk, criticality, and oversight tier assigned | Risk classification |
| Architecture | Approved deployment and integration pattern | Architecture decision record |
| Data readiness | Data is lawful, suitable, governed, and available | Data readiness assessment |
| Model selection | Model and provider are evaluated and approved | Model evaluation record |
| Development | Capability is implemented using approved practices | Technical documentation |
| Validation | Security, safety, quality, privacy, and resilience are tested | Validation report |
| Approval | Accountable authorities authorize production use | Production authorization |
| Deployment | Controlled release with monitoring and rollback | Deployment record |
| Operations | Service is supported, secured, and maintained | Operations runbook |
| Monitoring | Performance, risk, drift, use, and cost are observed | Monitoring evidence |
| Improvement | Evidence drives controlled changes | Improvement backlog |
| Retirement | Capability and associated assets are safely decommissioned | Retirement record |

Lifecycle gates and evidence rigor shall be proportional to the capability's risk, autonomy, data sensitivity, criticality, and external impact.
