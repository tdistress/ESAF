# ARC-P120 Retrieval-Augmented Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish ARC-P120 as a complete, validated RAG architecture pattern using separate knowledge-supply and query-execution pipelines with federated knowledge governance.

**Architecture:** Author ARC-P120 against the approved pattern contract and design, reuse the existing pattern-aware validator, and validate every control reference. Independent subagent reviews will challenge the control mapping and threat coverage before release records are finalized.

**Tech Stack:** Markdown, Python 3.13 standard library, Python unittest, GitHub Actions, Git.

## Global Constraints

- Knowledge-supply and query-execution pipelines remain separate.
- Query-time content and feedback cannot publish authoritative knowledge directly.
- Authorization is enforced inside retrieval before protected content or metadata is exposed.
- Retrieved content remains untrusted instructions.
- Citation rendering rechecks user authorization and exact source version.
- Model-only fallback is prohibited where grounding is mandatory and disabled by default for Tier 3 and Tier 4 material decisions.
- All referenced controls must resolve to authoritative ESAF control records.
