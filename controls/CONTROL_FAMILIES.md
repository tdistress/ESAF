# ESAF Control Families

**Status:** Working Draft

| Prefix | Control family | Purpose |
|---|---|---|
| GOV | Governance | Oversight, accountability, policy, and decision rights |
| STR | Strategy | Business alignment, objectives, and investment governance |
| RSK | Risk | Classification, assessment, treatment, and acceptance |
| IAM | Identity and Access | Human, machine, agent, and privileged access |
| DAT | Data | Data governance, protection, provenance, and lifecycle |
| MOD | Models | Model selection, integrity, validation, and lifecycle |
| APP | Applications | Secure AI application design and behavior |
| API | Platform and Integration | Gateways, APIs, tools, plugins, and integration controls |
| INF | Infrastructure | Compute, cloud, container, network, and platform security |
| AGT | Autonomous Agents | Identity, permissions, tools, memory, oversight, and shutdown |
| OPS | Operations | Availability, change, incident, continuity, and service management |
| MON | Monitoring | Logs, telemetry, detection, drift, and operational visibility |
| CMP | Compliance | Obligations, records, exceptions, and regulatory alignment |
| AUD | Audit and Assurance | Independent assessment, evidence, testing, and findings |
| EDU | Workforce | Literacy, role-based competence, and responsible use |
| ARC | Architecture | Approved patterns, trust boundaries, and design governance |

Control identifiers use a family prefix and three-digit number, such as `IAM-100`. Enhancements use parenthetical numbering, such as `IAM-100(1)`.
