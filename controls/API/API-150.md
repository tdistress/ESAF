# API-150 AI Interoperability and Portability

## Requirement

The organization shall document and test the interfaces, data formats, configuration, model dependencies, migration procedures, and exit criteria required to replace or isolate material AI providers and platform components according to continuity and concentration risk.

## Intent

Portability reduces lock-in, concentration risk, unsupported dependencies, and inability to respond to provider failure or unacceptable change.

## Applicability

Applies to E1 through E4 capabilities with material provider or platform dependency; testing rigor increases for E3 and E4.

## Implementation guidance

Use abstraction only where it preserves needed security and functionality. Maintain export formats, configuration records, alternative routing, compatibility tests, data-return and deletion terms, and migration runbooks.

## Expected evidence

- Dependency analysis, interface contracts, export tests, migration plan, alternative-provider or isolation test, and exit criteria.

## Assessment procedures

- **API-150-A1 - Examine:** Verify portability requirements and dependency records.
- **API-150-A2 - Test:** Export required data and configuration in a usable documented format.
- **API-150-A3 - Test:** Exercise isolation, alternate routing, or migration for a material dependency.

## Metrics

| Metric | Target | Frequency |
|---|---|---|
| Material dependencies with tested exit or isolation plan | 100% | Risk-defined |
| Exit tests failing recovery objectives without treatment | 0 | Annual |
